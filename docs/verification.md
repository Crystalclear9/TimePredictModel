# 实现与验证记录

复核日期：2026-10-15。范围为独立时间预测插件；外部 C2 密度、KV 映射及加载策略由接入方实现。

功能主线已实现，本地测试通过。现有证据不代表零缺陷或生产就绪，真实环境未验证项单独列出。

## 采集和重训修复

1. SSE 中相同的合法名称片段被错误去重，工具名与定义关联会出错。现在按协议逐片拼接。
2. 普通 OUT 被当作来源存活依据时，snapshot 会导出缺少 source_heartbeat 的删失样本，随后导致正式训练拒绝整批数据。现在缺少匹配心跳时单独排除，并检查心跳 TTL 有限。
3. 重训只比较数据/配置，候选包丢失、损坏或放错版本目录也会被当作可复用。现在先校验候选和版本，必要时重新训练；相同版本的损坏包先隔离为 `.invalid-*`，再重建。缺失、损坏和版本不匹配恢复均有回归检查。
4. 容量脚本的模拟预测缺少校准标记，实际一直降级 unknown。现在明确以测试分布执行 ready 数值路径，证据类型仍为 scale_acceptance，不能用于正式发布。

此前修复的跨轮次乱序、取消时序、错误工具 ID、严格 JSON、Windows 高精度时钟、UTF-8 模型文件、版本/租约和语义缓存并发回归仍保留。

## 清理范围

仓库保留插件主线、可选语义对照、AFT 兼容加载、测试、示例、补丁和部署/验收材料。移除旧代理数据适配、独立直接回归、合成回放、旧绘图和重复审计/WSL 脚本，相关命令与额外依赖一起移除。旧直接回归包给出明确错误，不再尝试导入已删除模块。

文档统一为 README 和 docs 下的数据、接入、验证三份；旧实验产物、重复审计结果、构建文件及缓存不作为交付材料。运行环境 `.venv/` 保留且不提交。历史实验代码可从 Git 历史取回。

## 接口边界追加复核

- 启动时拒绝 null/空租户、错误映射类型和非法令牌，防止空租户落入全量查询分支；保存验证后的映射副本，避免调用方后续修改改变隔离绑定。
- 非 ASCII Authorization 曾触发字符串常量时间比较异常并返回 500，现在统一返回 401，合法凭据仍可正常访问。
- 快照和通知处理中本地耗时曾被遗漏，批量建缓存会延长候选有效期。现在从消费入口记录单调时刻，缓存期限与 age 都计入处理耗时。

新增 12 项启动配置、HTTP 鉴权、租户隔离和慢消费者故障注入检查，覆盖已复现问题及配置绑定不可变性等回归场景。

## 通知恢复与缓存所有权复核

- 分页重放曾在共享状态已返回/取消后，继续提供尚未过期的旧候选。现在读取通知页后核对当前 generation、等待/预测状态和观察租约，关闭或失效时降级，不等待下一页 remove。
- 通知游标现在限制为规范 ASCII 数字及有效数值范围，异常输入返回422；通知流或状态读取中断返回503。
- 候选嵌套分布曾被输入行、返回行与内部缓存共享。现在读写缓存都复制完整候选，接入方修改外部对象不会改变后续结果。

新增15项分页关闭/取消、处理器失效、游标合法和异常边界、Redis读取故障及输入/输出别名检查；原有正常通知的时间推进和租户隔离检查保留。

## 跨入口、数值尺度与存储故障复核

本次发现并复现了三类主线问题：

1. 入口B的采集缺口/失联原先只影响B发出的调用，A发出但可能在B续接的调用仍可入窗并导出错误标签。现在保存故障时间区间，按两端时钟误差证明区间分离，阻断受影响候选及标签；恢复只放行区间后的新调用。支持迟到OUT、更早回返纠正及旧boot迟到事件，采集ID改为稳定的逻辑入口ID。
2. 微秒级调用配秒级H时，直接在[0,H]积分会漏掉概率质量。一个复现中真实截断成本约6.96微秒，旧结果约2.46e-34秒。现在使用稳定截断矩，窄窗口在单位区间积分；新增320组合的独立Z~N(0,1)积分对照。
3. 文件/目录fsync错误被忽略，正式发布复制的完整包也未同步。现在提交前同步文件与POSIX目录；CURRENT替换后的目录同步失败单独报告结果不确定，重训收据使用publication_outcome_uncertain。存储错误采用明确的故障注入，不是实际断电试验。

新增12项跨入口与稳定身份检查、7项数值检查（其中一项覆盖320组合）及4项存储故障检查。原有正常训练、发布、租约取消和接口测试保留。旧版状态缺少故障边界时保守降级，迁移步骤见README。

chronyc CSV字段布局另外对照了[上游输出函数](https://github.com/mlichvar/chrony/blob/master/client.c)，本次未发现字段偏移错误；这不代替真实chronyd和跨主机校时验收。

## 模型包与门禁追加复核

本轮先新增失败用例，再修复以下问题：

1. 清单漏列关键文件仍能加载，未列入摘要的动作适配文件也会影响行为。现在要求模型、特征和报告受摘要覆盖；v3包还要求编码器与数据清单，行为文件不得从清单外加载。包JSON拒绝NaN、Infinity及指数溢出。
2. 普通回归Booster、错误sigma、最佳迭代或时间缩放能被当作AFT加载。现在核对保存模型的normal AFT目标及scale、树前缀和训练报告，拒绝不一致配置及未知模式。
3. CURRENT可以指向目录外，附带材料可以覆盖模型文件或写到stage外。现在限制指针为目录内直接子目录，材料名必须为平面文件名并禁止覆盖核心文件，Windows大小写别名也拒绝。原先材料变化不改变版本，导致新内容被旧包静默替代；现在材料、曲线和动作适配配置一并参与内容版本计算。
4. 门禁曾接受无限支持量、越界概率、负Brier及布尔零计数，部分非对象报告段还会抛出类型异常。现在检查数值范围、样本整数类型、有效样本量上界和计数类型，异常报告返回拒绝。

新增41项模型包和门禁边界检查，模型相关用例使用真实CPU训练/加载，门禁指标使用明确的合成夹具；它们不构成实际服务器验收。原有正式标签训练、门禁拒绝/批准、原子发布、UTF-8包加载及存储故障测试仍通过。摘要检查不是签名认证，不能证明外部提供的训练报告或服务器证据真实。

## 可复现验证

```bash
uv sync --extra test
uv run --extra test python scripts/verify_plugin.py
uv run python scripts/verify_sglang_patch.py
uv run python -m compileall -q src tests scripts deploy examples
uv lock --check
```

当前 245 项本地测试通过。测试证据绑定源码 SHA256，写入 `outputs/plugin-verification.json`，明确包含 `server_acceptance_verified=false` 和 `production_publish_allowed=false`。Redis 事务、流和租约使用 fakeredis/Lua；发布验收对象是明确的模拟夹具。容量探针的本地测试也使用 fakeredis，并模拟内存查询。POSIX目录同步错误为模拟系统调用检查；Windows没有目录fsync验证。

补丁检查下载固定 commit 的三个原始文件，核对 SHA256、实际应用补丁并验证语法。它不导入 GPU 服务。构建检查另验证 wheel/sdist；本轮源码环境与独立安装的 wheel 环境分别运行完整245项测试并通过，未将同一套用例重复计数。
